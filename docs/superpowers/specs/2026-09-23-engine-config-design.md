# 检测引擎配置管理设计

## 目标

在检测引擎管理页为每个已注册引擎提供统一的配置入口、字段说明、健康检查和持久化配置，并让 API 健康检查、Worker 和实际检测任务统一使用数据库中的最新配置。

## 范围

首期覆盖当前已注册的三个引擎：

- Androguard
- AppShark
- MobSF

动态检测设计文档中尚未实现的引擎不在本期范围内。

## 配置模型

采用“公共字段 + 引擎专属字段”的结构。新增 `engine_configs` 表，每个 `engine_type` 唯一一条配置记录，包含普通配置 JSON、独立加密敏感配置 JSON、启用状态、最近健康状态、最近检查消息、检查时间、修改人及审计时间。

普通配置包括 URL、路径、超时和 JVM 参数；API Key、Token、密码等敏感字段独立加密存储，API 永不返回明文，仅返回已配置状态。保存时空密钥表示保持原值，并提供显式清除操作。

默认值来自当前环境变量或代码默认值，仅用于首次初始化；数据库中已有配置不被环境变量覆盖。

## 引擎字段

### Androguard

- 本地 Python 环境路径（只读展示）
- APK 解析超时时间
- 说明其由 Worker 本地执行，不需要服务地址

### AppShark

- Java 可执行文件路径
- AppShark JAR 路径
- 工作目录
- Android 平台目录
- 规则目录
- JVM 参数
- 扫描超时时间
- 日志级别及现有 AppShark 任务参数

健康检查验证 Java 可执行性及版本、JAR、EngineConfig、Android `android.jar` 和规则文件。

### MobSF

- 服务地址
- API Key（敏感）
- 连接超时
- 扫描超时

健康检查不再请求不兼容的 `/docs`，而是先确认根路径或登录页可达，再用 API Key 检查受保护 API，并区分不可达、未配置密钥、密钥无效和可用状态。

## 后端接口与权限

新增接口：

```text
GET    /api/v1/engines/{engine_type}/config
PUT    /api/v1/engines/{engine_type}/config
POST   /api/v1/engines/{engine_type}/config/reset
POST   /api/v1/engines/{engine_type}/health-check
```

引擎列表接口返回字段定义、普通配置摘要、敏感字段状态、帮助说明和具体健康消息，但不返回秘密值。

新增权限：

- `engine:read`
- `engine:write`
- `engine:health-check`

平台管理员拥有全部权限；配置修改和健康检查由后端强制校验。

## 适配器与 Worker

为适配器引入统一的配置对象或字典注入方式。引擎列表、健康检查和 Worker 执行都从同一配置服务读取数据库配置。

Worker 每次处理任务时按 `engine_type` 加载最新配置，在执行前再次健康校验；适配器实例使用数据库配置覆盖环境变量默认值。执行记录保存脱敏后的配置快照，禁止写入 API Key 明文。

现有任务配置保持兼容；任务级配置不在本期替代全局配置，后续可作为受控覆盖扩展。

## 前端交互

引擎卡片继续展示名称、版本、能力、描述和状态，并新增：

- 配置
- 环境检查
- 说明

配置使用抽屉或弹窗，包含说明区、按引擎动态生成的表单、字段级问号提示和保存/重置/取消操作。MobSF 显示 URL、API Key、连接超时和扫描超时；AppShark 显示路径、JVM 和超时字段；Androguard 显示本地运行信息和解析超时。

密钥只显示已配置状态，不回显明文。保存成功后自动刷新状态；失败时显示后端具体原因。说明内容由后端注册信息提供，包含用途、依赖、字段解释、启动命令、健康检查规则、常见错误和文档链接。

## 错误处理

前端做格式校验，后端执行完整字段和权限校验。健康检查和执行前都验证环境；错误信息区分服务不可达、认证失败、路径缺失、Java 版本不足、规则/平台库缺失等情况。日志和执行记录对 Authorization、API Key、Token 和密码统一脱敏。

## 数据库迁移与兼容

通过 Alembic 新增表并初始化三个已注册引擎的默认记录。不得重复初始化业务数据。现有任务和执行记录保持兼容；未配置 MobSF 时保留原有任务行为但提供更具体错误信息。

## 验收

后端验证配置 CRUD、权限、加密脱敏、重置、三类健康检查和 Worker 配置注入；前端验证动态字段、保存/取消/重置、密钥状态、说明弹窗和错误提示。实际验收包括配置 MobSF 地址与 API Key、健康检查、提交检测、确认 Worker 使用数据库配置、确认执行记录脱敏，以及 API/Worker 重启后配置仍保留。
